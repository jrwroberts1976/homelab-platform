# Network host detail coverage — 29 September 2026

The live audit on monitor-01 found **50 current MAC-keyed devices**.

The raw checklist reported **0 fully complete records**, but that number is
deliberately strict and should not be read as 50 unknown machines. It required
every device to have hostname, OUI vendor, Nmap OS, an observed open port, a
DNS signal and an automatic device-type hint. Those fields are not all
appropriate for every device.

## Raw missing-evidence counts

| Field | Devices missing it |
|---|---:|
| Hostname | 8 |
| MAC/OUI vendor | 12 |
| Nmap OS match | 45 |
| Observed open TCP port | 44 |
| Bounded DNS signal | 46 |
| Automatic device-type hint | 49 |

## Important interpretation

- Many managed infrastructure hosts already have stronger authoritative OS
  facts from canonical IaC and Zabbix. Lack of an Nmap match is not an OS gap
  for those hosts.
- Seven of the twelve blank vendor records use locally administered MAC
  addresses, so a public OUI vendor lookup is not meaningful for them.
- Most `baseline` records are waiting their turn in the controlled seven-day
  profiling backlog. They should not be force-scanned simply to make this
  table complete.
- A zero open-port count on a baseline record means "not yet profiled", not
  "no ports open".
- DNS evidence is intentionally sparse. A host does not need a recognisable
  DNS signal to be considered known.
